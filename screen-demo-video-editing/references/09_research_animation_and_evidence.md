# 科研数据动画：染色、三维投影、层序试错与验收

## 先区分结果与展示

- **输入边界：** 本章将已有坐标、分组、候选序列和评分变成动画，不自动生成科研结论。新增计算须属于用户另行授权的分析任务；没有结果就用明确标为“示意”的合成数据，不能填入想要的成功率。
- **三份记录：** 保存不可变原始数据、算法输出、展示状态。展示层可提亮、染色、插值、变速；不得回写算法输入或把排版坐标当作 PCA 坐标。
- **真实与编辑摘要：** 复用旧 GUI 轨迹、新计算动画及编辑后的对话卡片时，在项目说明区分来源。不要把编辑摘要称为模型本次真实自主运行，更不以可视化替代实际工具执行记录。
- **数字口径：** 总输入、目标数、缩略图数、派生切面数分别记录。辅助器官裁剪图不能冒称完整 CT 切层；隐藏未满末排时，图墙展示数与总输入数可以不同，说明各自口径。组合数是明确假设下的理论规模，不是模型实际遍历的次数。
- **数据分离：** 有已知顺序的受控打乱实验可用于回顾性评价，源层号放独立 evaluator。若方法使用参考图、种子、先验或标签，应准确记录，不能宣传为完全无监督筛选。

## 透明染色：颜色明显，纹理仍可辨认

- **黑底问题：** 直接向暗 CT 叠少量颜色，颜色容易被黑底吞掉；直接实色填充又会抹掉结构。仅在展示纹理中先抬高黑位、降低对比度，再叠色；原灰度图、窗宽窗位与分析数组保持原样。
- **可调起点：** `scripts/research_animation.py` 的 `tint_texture()` 默认用 `0.43 + 0.42 × RGB` 提亮，再混入 58% 组色；输入 RGB 归一化到 0–1。这是低对比缩略图的起点，不能用来改变医学观察图的灰度含义。
- **颜色语义：** 区分固定身份、当前组归属与临时高亮。组色由稳定 `group_id` 决定，不按每帧排序位置循环上色；组归并时可向父组颜色渐变。左右分区用两个色族，族内用色阶；最终跨区合并时统一调色逻辑。
- **纹理与 alpha：** 原始黑白版本、染色前后版本在实际播放尺寸比较；确认纹理仍有变化、组色可分、透明边缘未变实色。使用有间隔的稳定样例，不把同一张图复制成大量假输入。
- **性能：** 缓存 `(image_id, size, group_color, display_style)` 对应纹理；不按连续插值色无界缓存。插值两端有限个纹理，避免给每张卡片分配整幅画布。atlas 可缓存多分辨率，切换时检查细节跳变；放大 28 px 源图不能恢复原细节。

```python
from research_animation import tint_texture
display = tint_texture(raw_image, '#298bb4')  # 新图；不改 raw_image
display.save(project_dir / 'display_only.png')
```

## 三维聚类展示：位置来自结果，相机服务可读性

- **术语准确：** PCA 是降维投影，聚类标签来自实际聚类/筛选结果。图像点在二维画面聚成团，不证明高维样本可完全分离，也不证明属于同一患者。
- **坐标冻结：** 保存一次实际 `N×3` 坐标、固定样本 ID、类别和筛选掩码。所有点只接受共同中心化、统一缩放及同一刚体相机；不能单独把目标簇往外挪、拉伸某一轴或隐藏困难样本来制造分离。
- **随机到聚合：** 固定 seed 生成演示起点，再按稳定 ID 插值到实际投影坐标。此运动表示“组织成特征视图”，不代表 PCA 的真实迭代轨迹。若展示优化过程，改用实际保存的迭代状态。
- **相机连续：** 首段维持同一个共同视角，聚合完成后再缓慢旋转，避免同时改变太多变量。两端相机用旋转插值 `slerp_camera()`；逐元素线性混合相机矩阵会产生非刚体缩放/剪切。
- **共同选角：** 对候选 yaw/pitch 评估目标的可见数量、与非目标点的最近距离第 10 百分位和中位数；优先避免裁切，再改善多数目标点的可辨认度。单看均值会让少数离群点支配选角。不能将点间屏幕距离称为聚类准确率。
- **空间安全：** `camera_report()` 的 viewport 和遮挡框均为最终画面像素；将右侧缩略图、标签、安全边距也作为遮挡区。记录最终 basis、可见点数和最近距离；距离为点中心间距，至少还需比较点半径之和。
- **深度与强调：** 所有点按投影深度排序绘制；目标半径/颜色可强调，背景可变淡但保留全量。选角无法消除真实重叠时，用局部放大或引线，不能承诺一定找到分离视角。

```python
from research_animation import normalize_cloud, camera_basis, camera_report, slerp_camera, project_cloud
points, transform = normalize_cloud(actual_pca_coordinates)
before, after = camera_basis(20, -15), camera_basis(-25, 10)
basis = slerp_camera(before, after, eased_progress)
xy, depth = project_cloud(points, basis, center=(640, 420), scale=220)
report = camera_report(points, target_mask, basis, viewport=(20, 100, 1240, 640),
                       center=(640, 420), scale=220, radius=5,
                       occluders=[(1040, 100, 220, 480)])
# 按 depth 排序绘制 xy；目标数取掩码计数，不从可见点倒推。
```

## 方向校正、局部分组与排序试错

- **方向校正两种表达：** 介绍可用各图独立的真实修正角度（包含无需旋转的图），研究段则用四向匹配评分、候选矩阵和批量扫描进度。不要让所有 CT 统一转一圈，也不要重复两个几乎一样的旋转镜头。
- **分区需有依据：** 按实际可测特征、采集序列或已有类别划分，并写短标签。数量由分组结果决定，不强行为左右对称。组边界虚线只在独立求解时显示，跨区合并时淡出；标签/侧栏不改变两窗口高度和固定间隙。
- **归并可观察：** 给每张图固定 ID；每轮保存 `order`、与其对齐的 `groups`、真实 `quality`。短相邻块先在各分区内部合并，再跨区联合。`interpolate_tiles()` 根据 ID 连接前后位置和颜色，不把“第几个位置”当作图片身份。
- **失败要有证据：** 如果实际方法比较中有失败，可依次呈现“候选尝试 → 一致性未通过 → 撤回 → 新约束下重求 → 合并”；失败短暂停住并用低饱和提示线、轻微位移或撤回轨迹区分。无真实失败时不要为了戏剧性制造一次，更不要把颜色/抖动当作已验证的算法失败。
- **曲线与动画同源：** 每个显示状态对应同一份候选及评分。初值按实测，随机顺序也可能有正确相邻对；允许首轮上下波动、回退和方法切换。不要手绘一条从零必然单调上升的“正确率”。只有 evaluator 有源顺序时才能叫顺序正确率，否则用明确定义的一致性指标；相似度不冒充准确率。
- **不泄露答案：** 算法先固定候选，再由 evaluator 评价；禁止将正确率反馈给本应无标签的方法选序。若实际方法用了标签，就照实注明。完整逆序是否等价、方向是否按物理位置确定，均在项目中记录。
- **跨段连续：** 最后一帧的图片 ID、位置、组色必须等于下一段起点。状态切换和曲线揭示用同一个成片时钟；一个动作不能先显示最终满分、图像却还在错误顺序中移动。

最小状态结构如下；文件只是展示接口，不负责求解：

```json
{"states": [
  {"order": ["slice-b", "slice-a"], "groups": ["g1", "g2"], "quality": 0.35},
  {"order": ["slice-a", "slice-b"], "groups": ["g3", "g3"], "quality": 0.31}
]}
```

`validate_sequence_trace(states, image_ids)` 检查每个状态均为同一身份集合的完整排列，允许评分下降；项目另存评分定义、方法名、候选来源和时间。

## 固定介绍边界、排版与最终报告

- **硬时间先行：** 若用户明确介绍必须在某秒结束，这个边界不因新增停留自动后移。先锁定近景停留、患者任务和流程页的最低可读时长，在标题或转场内调配；预算不够时说明冲突。帧预算见 [08](08_exact_timing_and_source_quality.md)，这里的 17 秒或 2 秒只是项目参数。
- **冻结正确状态：** “平铺停留后再拉远”需要冻结拉远前的相机状态，不冻结已经拉远一部分的首个导出帧。近景和全景使用同一固定 viewport，仅修改内部裁切/倍率；别把小图墙扩张冒充镜头拉远。首屏边缘完整规则继续按 [07](07_storyboard_and_animation.md)。
- **文字组统一移动：** 标题、患者背景、任务和公式共享一个 `(x,y)` anchor 和相对偏移，按文字 bbox 及左右图文留白确定位置。用户要求字体一致时同时统一字体、字号、字重，不只字号；公式指数单独排版，单位文字放同一行，删掉重复的近似数值行。
- **进度条与卡片克制：** 一个阶段导航即可，不再把每个运行状态套多层框；待完成文字保持可辨认的中灰，完成节点变深色。普通步骤、工具、截图与交付靠几何图标和结构区分；是否用 emoji 遵从项目样式，检查字体缺字。完成节点数量可作为静态图层缓存 key。
- **清单交付：** 先逐行显示工作项，再绘制勾线；报告最后给实际结果图和依据足够的观察文字。完整停留从最后一句文字、最后一项勾和对话滚动稳定后开始算。绿色勾等具体配色属于风格选择，不是科研有效性的证据。
- **候选结论：** 需要回到原始图像核对，注明尺度/采样与分割局限。没有参考诊断时写候选观察与需专业复核；不能从某个高密度等值面直接宣布疾病。

## 增量导出与分层校验

| 校验对象 | 必须检查的可观察证据 |
| --- | --- |
| 纹理染色 | 源像素未写回、alpha 保留、纹理仍可辨、组色稳定；在真实背景和播放尺寸检查 |
| PCA/相机 | ID/坐标文件哈希固定、共同旋转保持三维距离、basis 正交且右手、目标可见数量与遮挡距离 |
| 排序状态 | 每帧相同 ID 集，无丢失/重复；合并前后身份连续；失败/重试/曲线对应同一候选事件 |
| 近景停留 | 对已编码视频的完整停留区间解码检查静止，随后确有运动；固定 viewport 外像素不变 |
| 阶段边界 | 在明确的帧号抽出切换帧，与下一段第一帧比较；不只看 JSON 标称秒数 |
| 报告 | 最后一项/最后一句完整后仍留足静止帧；检查实际冻结帧，不以动画总长替代完成后停留 |
| 增量改版 | 只重渲染改动层或片段，其余复用已验证段；拼接前统一轨道 timebase，核对每段帧数、PTS/DTS 连续性和解码 |

- **测试工具：** `smoke_research_animation.py` 生成明显为合成数据的纹理、3D 云和候选序列，运行失败撤回与改善动画，导出 FFV1、静帧、接触表和 JSON 证据。只验证展示工具，不证明真实分析效果；运行方法见 [06](06_validation_and_recipes.md)。
- **证据范围：** PNG 正常不证明成片正常，源预览像素一致不证明有损编码后逐像素一致。停留比较可用低分辨率亮度误差容限，改版片段的无重编码复用则比较压缩包或解码帧；容限及范围写清楚。
- **项目归档：** 保留版本化时间轴、source/算法/显示坐标哈希、随机 seed、候选与评分、相机、阶段时间、真实成片抽帧及完整解码记录。公共 skill 只提交通用代码和合成样例，不提交患者图像、私有路径、日志或音乐。
