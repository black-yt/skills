# 分屏、悬浮与镜头

## 拆分后期素材

```bash
python3 scripts/split_video.py ./source.mp4 --split-x 480 --output-dir ./parts
# 仅对适用的 H.264 明确选择免重编码显示裁切：
python3 scripts/split_video.py ./source.mp4 --split-x 480 --output-dir ./metadata_parts \
  --method h264-metadata
```

- 普通 `crop` 改像素，必须重新编码；使用高质量参数或明确无损中间格式，不要声称 `-c copy -vf crop` 可行。
- H.264 的 `h264_metadata` 可改 SPS 显示裁切而不重新编码图像数据。工具只改左右 offsets，保留原本为宏块补齐的底部裁切。
- 该方法输出体积通常接近原片；它不删除压缩码流中被遮住的内容，**不用于脱敏**。要求数据物理移除时用真正裁切重编码。
- 不同播放器或后期软件可能对显示裁切处理不同。检查实际解码宽高，并在开头、中间、末尾与源片对应区域逐像素哈希比较；不通过就不要交付为“像素一致”。
- 左右素材从同一帧裁切、保留同一时间轴与音轨，方便未来同名配对。不要分别按手工时间重建两份素材。

## 悬浮布局

- 分开配置 **输入 crop** 与 **输出 rect**。素材原比例保持不变，背景 cover/fit 策略明确；不要通过拉伸 UI 填满剩余空间。
- 圆角用灰度 alpha mask，投影用独立透明层。背景、投影、视频依次叠加，避免把会移动的投影提前烘焙在静态背景上。
- 主桌面和日志的组合长宽比限制了双面板能铺满的高度。先缩小左右边距和中缝，不能为了铺满而裁掉按钮或挤扁窗口。
- 给阶段标题和字幕预留空间。例如主窗上方 136、下方 196 的差异是某次构图选择，不是所有画布的固定规则。
- 微调位置只改 rect 的 x/y；只调宽度则按 crop 比例同步计算高度。移动后重新检查文字是否遮住画面。

## 常驻侧栏与可选退场

- 需要持续说明模型在操作时，省略 `transition`，保持窄侧栏全程可见。先按主屏幕 crop 比例决定主窗高度，再令 `secondary.rect` 与它顶部、底部对齐；不挤扁主画面来凑高度。聊天可按自己的尺寸渲染后等比放置，确认字体在最终成片仍清晰。
- 观察和动作的流动箭头可用 `render_flow.py` 制作透明 MKV，在 `overlays` 对应项加 `"loop": true`。标签、箭头和字幕避让；短视频 EOF 默认保持末帧并不等于循环，见 [07](07_storyboard_and_animation.md)。


- 外层主窗的 x/y/w 使用 smoothstep 缓入缓出；辅面板同时向画布外移动。转场持续时间依节奏，短演示可从 0.5–0.8 秒试起。
- “第二轮结束”应定位到执行反馈完成时刻，不能偷换为模型输出出现时刻，也不必强行向上取整到下一秒。
- `transition.start` 可以是秒数，也可以是 `{"event_step":2,"field":"executed_at"}`；后者从 `events` 文件解析。
- 对话和退场各自独立：消息流持续播放，合成器只改变位置；不因为触发退场就截掉后续消息。
- 让主视频决定成片时长。辅流、短对话源或某个 PNG 到 EOF 时，不用 `shortest=1` 把整片提前截短；必要时保持辅流末帧，退场后由 enable 隐藏。

## 内部缩放与跟随

- 外层面板保持固定比例与尺寸，内部 `zoompan` 只改变 source viewport。`visible_fraction=0.4` 表示宽高各留 40%，不是放大到 40%；对应约 2.5 倍。
- 鼠标事件使用源录屏像素，并减去主 crop 原点；再把取景限制到 `0..iw-iw/zoom`、`0..ih-ih/zoom`，避免屏幕边缘出现黑边。
- 操作密集的小面板、参数输入和难找按钮可用局部；加载完成、切层结果、全局布局变化和最终三维运动优先全景。
- 不是每次鼠标移动都推进镜头。对相邻操作合并窗口，短暂停顿保持同一构图，长等待回全景，减少“拉近—拉远—再拉近”的呼吸感。
- 合并窗口要保护应展示全景的关键状态，不能只按时间 gap 盲合并。工具可设置 `merge_gap` 和可选 `max_segments`，但段数限制取决于用户需求，不固定强制五段。
- 快速推进/拉回可以用 0.2 秒，跟随稍缓；对复杂动作应根据实际运动调整，不能把本次参数变成永久默认风格。

## 动态透明合成的已知陷阱

逐帧改变尺寸的 RGB 视频进入格式转换、`alphamerge` 或 overlay 后，某些 filter negotiation 会仍沿用首帧尺寸。结果是投影已展开，画面内容却停留在初始大小；单帧预览可能完全正常。

工具的修复形态是：

```text
source crop → 内部 zoompan → 动态 scale
           → pad 到固定最大 W×H → format=rgb24
mask       → 相同动态 scale → pad 到相同最大 W×H → format=gray
           → alphamerge → overlay
```

- RGB 和 alpha 都要固定画布，透明区域的 mask 必须为零。
- 抽查连续视频在转场前、中、后以及特写时的实际几何，不能仅确认命令成功、时长正确或静帧漂亮。
- 脚本的短测参数 `--duration` 与单帧 `--preview-at` 服务不同验收目的；最后仍需完整导出和解码。

## 重复导出与静态层

- 合成器将 PNG 输入解码一次，在滤镜中缓存循环，避免高分辨率背景和 mask 每帧读取。视频动效仅在明确设 `loop: true` 时循环。
- 需要后续多版调速时，可设置 `encoding.codec: "ffv1"` 并输出 MKV 合成母版，再做最终一次 H.264 编码；这保证合成后 RGB 保存无损，不代表缩放前原像素未变，见 [08](08_exact_timing_and_source_quality.md)。
