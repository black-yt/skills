# 精确时长与源画质

## 分清四种文件

| 层次 | 内容与修改边界 |
| --- | --- |
| 原始录屏 + EDL | 原片只读；静止、周期和头尾删除记录在源时间，重新剪辑仍从原片建立 |
| 源画面无损母版 | 选取、裁切、CFR 采样后的原始像素，用 FFV1 和逐帧哈希证明，不能声称保留了被删除帧 |
| 合成无损母版 | 面板、镜头、文字和箭头已合成的 RGB 画面；对这张合成画面无损，不代表没有缩放或重采样 |
| 交付 MP4 | 一次 H.264 编码；CRF 16/18 是高质量有损；加音乐尽量复制已确认视频流 |

- **改版重走来源：** 不把上一份有损成片当新源反复导出。记录原片、EDL、字体、配置、输入哈希及脚本版本；明确本次改哪一层，其他层复用已验证素材。
- **“高清”有边界：** 高输出分辨率不能补出原录屏不存在的文字细节。源像素哈希、合成像素无损与最终视觉清楚是三种不同证据。
- **中间格式代价：** FFV1 占空间和 I/O，先检查磁盘；可只保留需要重复修改的母版，不为所有临时 PNG 盲目生成长片。

## 从原片建立可验证母版

```bash
python3 "$SKILL_DIR/scripts/lossless_master.py" --config ./master.json
```

- `assets/master.example.json` 指定原片、源区间、cuts、crop、fps；输出 MKV。脚本在同一解码支路完成裁切/CFR 采样，然后分别编码 FFV1 与计算原像素 framehash，再解码母版比较全部帧。
- 保留源 pixel format，色度子采样的裁切必须对齐：例如 YUV420 的 x/y/w/h 都为偶数。遇到 FFV1 无法原样支持的格式会拒绝，不能悄悄转换后称逐像素无损。
- 证明范围是“本次选帧、裁切之后的像素”，不包含被删内容，不证明保留原 VFR 每一帧。帧数、哈希文件和配置保存在 `.master.json` 旁。
- 此工具只处理画面；有原声需要按同一 EDL 单独同步。仅要免重编码左右素材时先考虑 [03](03_panels_and_camera.md) 的 H.264 显示裁切，并记住它不能脱敏。
- `render_presentation.py` 可设 `encoding.codec: "ffv1"` 并输出 `.mkv`，建立可反复调时长的合成母版；默认 H.264 交付保持不变。

## 先分配帧数，再调速度

```bash
python3 "$SKILL_DIR/scripts/retime_video.py" --config ./retiming.json
```

使用 `assets/retiming.example.json` 建立片段列表。该工具只处理画面：来源包含音轨时需显式 `discard_source_audio: true`，否则拒绝，避免无意丢掉原声。

- **整数帧合同：** 总帧数 `F = target_seconds × fps`。例如 60 秒、20 fps 为 1200 帧，GUI 必须在第 17 秒开始则前段共 340 帧。使用有理数帧率，不能表示为整帧的秒数会报错，不静默取整。
- **固定与弹性：** 标题、背景解释、结果交付停留、品牌时长先定；仅一个片段设 `fit: true` 吸收剩余预算。缩短 logo 1 秒后，这 1 秒自动留给弹性操作段，其他段不动。
- **速度公式：** `速度倍率 = 源片段秒数 / motion_frames对应秒数`。整体等比例减速必须同时减速 GUI、对话、截图、箭头高亮和字幕；最稳妥的是先合成同步母版，再对完整母版调速。
- **分开运动和停留：** `duration_seconds` 是本段播放时间，`hold_seconds` 是追加的静止停留。结果摇摆、生成消息、最终稳定停留不要混作同一段。
- **稳定交付帧：** hold 冻结最后一张重采样后的显示帧，不自动识别“结果已经出现”。`source_end` 要在图片、说明文字和自动上滚都完成之后；检查实际冻结帧。关键交付只在源片最后一帧出现时，显式提取确认的 still 作为独立停留段更可靠。
- **避免少一帧：** CFR 转换在 EOF 附近可能少一帧；工具先对有效末帧小幅 padding，再 trim 到明确帧数，并校验解码帧数。不能拿延长黑帧或旧帧替代缺失的实际操作。
- **审计映射：** `.retiming.json` 保存每段 start/hold/end 帧、源区间、源哈希和校验。`map_source_time()` 只映射运动区间，片段右边界为开区间；追加 hold 不是原日志时间。
- **帧上限与冲突：** 固定段已占满预算、多个 fit 段、重复 ID 或源区间越界都应报错，不能随意压缩用户确认的品牌/交付停留来凑时长。
- **固定阶段结束点：** 新增近景停留时先在该阶段内部重新预算，不能自动推迟已约定的介绍结束帧。拉远前的完整静止和拉远后的稳定全量应分开计帧；具体状态验证见 [09](09_research_animation_and_evidence.md)。

## 多条时间轴必须一起变

- **先源时间，后成片时间：** 日志时间通过一个可靠动作锚点对应原片；先扣 EDL cuts，再做速度映射，最后加介绍片偏移。中间重新剪掉片段也要同步消息与鼠标轨迹。
- **数据与展示分开：** 原日志保留真实时间；为叙事提前/延后展示的结果图片明确标为 editorial，不改写历史记录伪装其真实出现时间。
- **同轮多事件：** 一轮可能依次有观察截图、模型输出、工具调用和执行反馈。用 `executed_at` 锚定完成反馈，不能抓到同轮第一张截图就以为动作完成。
- **最后一次调整：** 最后交付画面冻结 3 秒是一个展示要求；要确认最终画面中的聊天没有还在上滚，阶段标题和字幕也适合停留。

## 可以复制的片段与音频

- **H.264 copy：** `kind: "copy"` 只允许从第 0 秒开始、与目标尺寸/帧率一致的 H.264 前缀，无额外 hold；必须在合适的 GOP 边界结束并验证实际解码帧数。失败应退回原母版重编码，不能假装复制成功。
- **哈希范围：** 工具验证 copy 中间片段的压缩 packet 哈希；concat 可能注入参数集，不能把这份证据扩大成“最终文件字节完全相同”。需要最终证据时检查最终输出对应帧的解码像素，或单独证明实际输出 packet。
- **不能 copy 加滤镜：** 缩放、文字、裁切像素和变速都需要处理视频；`-c copy -vf ...` 不成立。只改封装元数据与实际裁切不同。
- **混合时间基：** 拼接外部 MP4 片段前逐段 remux 成同一 video track timebase，仅在最终 mux 指定 timescale 不会修复此前被误读的段内时间戳。帧数正常仍可能存在时钟跳变；核对归一化前后 packet 哈希、全片展示时间网格与解码时间增量，B 帧的 PTS 需按展示顺序检查。`retime_video.py` 已为自己的输出片段设置统一时间基，外部自制拼接也要做这一步。
- **音乐在最后：** 纯背景音乐可在最终时长锁定后混入，`mix_audio.py` 复制视频流。时长不变时检查是否能复用既有 AAC；时长变了就重新计算音乐淡出，不能把旧版末尾的淡出留在新中段。
- **原声与旁白：** 不能用“最后再配乐”代替原声同步。含讲解、点击声的源片变速需同段同步音频；有意义的语音保留自然语速时应重排镜头，而非只拉长静音画面。

## 执行与交付

- **工具版本：** 先查本机 `ffmpeg -version` 和对应 filter/encoder 的 CLI help；参数在不同版本可能变动。本次合成回归使用 FFmpeg 9.0.2、Pillow 13.0.0、NumPy 2.5.4，不将这些版本设为永久要求。
- **持久环境：** 依赖装在项目专用虚拟环境或用户指定环境，避免放在会清理的临时目录；不修改共享 site-packages，不把依赖或实际媒体提交到 skill。
- **减少无效 I/O：** 静态 PNG 解码一次后在滤镜内部 loop；逐帧重复读大背景会显著拖慢渲染。图片输入显式帧率，视频循环和末帧重复按素材用途区分。
- **长任务可追踪：** 保留 FFmpeg 错误日志和进度；后台进程要跟进到退出并检查文件，不以“已启动”当完成。临时输出通过校验后才替换目标，失败保留诊断而不覆盖原素材。
- **分层验收：** 关键 PNG → 短动态片 → 全片解码/帧数 → 源/输出哈希适用范围 → 实际音轨 → 首尾真实播放器。不要因为缩略图命令失败就重编码已正确的整片，也不要因为单台播放器卡顿无证据删尾。
