# 背景音乐与旁白

## 先区分需求

- **配乐：** 用户提供音乐或允许选曲，只处理背景音量、片段、循环和淡入淡出，不擅自生成讲话。
- **配音：** 需要旁白脚本、语种、声音和时间位置。工具支持已提供的语音文件；没有自带 TTS、声音克隆或某家 API 的调用代码，不声称已经合成真人语音。
- **TTS 接入：** 只有用户需要且现有服务可用时，先按该工具接口生成旁白文件，再走同一条混音流程。不要虚构接口参数或把音乐导出称“配音完成”。
- 音乐、旁白和软件原声分开保留。素材来自用户项目，不将歌曲、声音文件、字体或凭据打包进公共 skill。

## 音量与结束方式

- 测量选定片段的 integrated LUFS 和 true peak，再决定增益；音乐原片可能已经非常响，直接按音量百分比容易不一致。
- 背景音乐可从 −22 LUFS 试起，有旁白时通常还要降低或 duck；旁白可从 −16 LUFS 试起。它们是试听起点，不是所有内容的强制标准。
- 两遍 `loudnorm` 使用第一次测得的 I/TP/LRA/threshold/offset，避免以为“0.35 倍”一定柔和。最终混合后再测峰值，防止叠加削波。
- 音乐按视频时长截取，保留自然开头；例如 2 秒淡入、4 秒淡出。时长更短时缩小这些值，不能把整段吞进渐变。
- 需要循环时在配置显式启用；不要把短曲静默填到片尾。循环接缝本身也应试听，工具不会自动找到音乐乐句边界。
- FLAC/MP3 可能带专辑封面 video stream，必须明确只取 `a:0`；输出画面只取已经确认的主视频 `0:v:0`。

## 旁白对齐与压低音乐

- 旁白先规范音量，再用 `offset_seconds` 对齐到成片时间，`adelay` 的单位是毫秒。
- 短旁白经过 `loudnorm` 时可能在 EOF 一次 flush，出现大音频帧或 NOPTS；直接串延迟和混音，在部分 FFmpeg build 中可能丢失前置静音或产生时间戳空洞。工具先把规范化结果写为浮点 PCM，再以正常采样帧执行延迟；不要只改 PTS 就认定声音位置正确。
- 语音短于视频时，用 `apad` 和 `atrim` 保持全片长度；不要用一条短语音的 EOF 截断主片或背景音乐。
- 旁白分成两支：一支参与最终混合，一支作为 `sidechaincompress` 的控制信号；人声出现时降低音乐，人声结束后平滑恢复。
- 软件原声可保留并独立调整 `source_gain_db`。不要把有意义的提示音当作噪声自动删除。
- 新编排的音乐/旁白可按连续采样重建 PTS；已与画面对齐的原声用异步重采样保留时间空隙，不能为了连续而把原来的时间间隔全部压掉。
- 限幅只防止峰值溢出，不替代响度平衡。需要试听旁白清晰度、音乐情绪、淡出是否自然，以及是否出现剪口爆音。

## 配置与调用

```bash
python3 scripts/mix_audio.py --config ./audio.json
```

`assets/audio.example.json` 展示音乐和现成旁白一起使用；只要音乐时删去 `voiceover` 即可。`music.start_seconds` 选择曲目起点，`voiceover.offset_seconds` 决定它在视频里何时开始，两者含义不同。

- **画质：** 使用 `-c:v copy`，不重做镜头和字幕；正式导出常用 AAC 256 kbps、44.1 kHz 立体声。视频数据哈希必须和输入一致。
- **验收：** 检查实际总时长、完整解码、最终 true peak 和非静音音轨；元数据音量不等于实际声音。
- **证据边界：** 合成素材的正弦信号测试能验证延迟、混音、ducking 与视频包不变，不能替代真实人声的听感验收。

```bash
python3 scripts/validate_export.py ./final.mp4 --compare-video ./presentation.mp4 \
  --burned-only --report ./final.validation.json
```
