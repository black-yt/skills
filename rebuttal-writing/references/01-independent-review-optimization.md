# 独立子 agent 驱动的多轮 Rebuttal 优化

## 目标与分工

- **目标。** 用独立审稿视角发现 rebuttal 尚未回应、证据不足或容易引起新误解的地方，反复改进到现有证据能支持的最好版本。分数用于观察判断变化，不能替代问题是否解决。
- **主 agent。** 掌握历史轮次、核查来源、维护问题台账、修改回复并组织下一轮；不能把自己的解释当成独立评审已认可。
- **审稿子 agent。** 站在指定 reviewer 的原始关注点上独立判断本轮回复，只写 verdict，不直接改回复。允许接受、维持拒绝或降低评分；检查原问题和回复新增问题，不以找茬数量衡量质量。
- **每轮隔离。** 每位 reviewer 每轮新建 agent；可用时设置 `fork_turns="none"`。不向其传递历史评分、优化记录、其他 reviewer 意见、期望分数或“只差你通过”。若默认指南等不可避免地暴露历史，记录暴露范围，不能宣称完全盲评。

## 首轮准备与输入冻结

1. **定范围。** 记录允许的事实核查、稿件修改和补实验范围；遵守已有的轮次、时间或资源预算。用户要求继续优化已授权的回复时，直接推进可执行修改，不因新一轮就重复请求确认。
2. **定量表。** 使用当前任务提供或已核验的会议评分含义。没有可靠量表时，报告 concern 状态和总体判断，不编造官方分制。用户的目标仅由主 agent 维护，不写进审稿提示。
3. **冻结材料。** 保存完整投稿论文及附录、该 reviewer 原始 review、本轮完整回复及其全部发布块；记录文件清单、版本与 SHA-256。必要的新增证据应以回复中可见、可定位的补充材料提供，不能只在作者内部笔记里存在。
4. **限制读取。** 给 agent 明确的输入清单及专属输出位置，禁止浏览其他轮 verdict、问题台账与其他 reviewer 的回复。评审中不补塞会改变判断的新事实；新事实进入下一轮。
5. **合理并行。** 多位 reviewer 可并行评审各自回复；结果全部收齐后逐一核查。未产出判定不等于通过；执行失败的有限重试保留原因与替代关系，不能替换已完成的负评。

## 可复制的独立评审提示

```text
请独立评估对 Reviewer [ID] 的本轮 rebuttal。
只读取以下冻结材料：[完整论文及附录]、[原始 review]、[本轮全部回复块/公开补充]。
不读取其他 reviewer 的意见、历史 verdict、作者问题台账或优化记录；不修改回复。

先读论文，再逐项判断原 review 的 weakness、concern 和 question。
对每项报告：
- 已解决 / 部分解决 / 未解决，以及本轮回复的准确位置；
- 仍可能不满意的具体原句、缺失回答或证据缺口；
- 该问题怎样影响主要贡献或结论，是决定性阻塞、可修订不足还是可选扩展；
- 最低需要怎样的澄清、已有证据或新证据才能改变判断。

另外检查回复是否新引入矛盾、错误归因、统计分母问题或无法兑现的承诺。
区分措辞改善、作者确认、已有受控实验和新增实证，不把修订承诺视为已完成结果。
按 [当前会议量表及含义；若未知则省略评分] 给出总体判断、置信度和决定性理由。
允许认可已经回答的问题，也允许维持或降低评分；没有预设结果，不自动追加更高门槛。
将完整 verdict 写入 [专属输出文件]，记录实际阅读的材料和版本。
```

## 从不满意判定到实际修改

先读完整 verdict，提取决定性理由，再核对论文、回复和来源。不能只看分数，也不把 agent 的每个猜测当成事实。内部维护下表，不复制到正式回复：

| 问题 ID / 回复位置 | 不满意的原因与影响 | 来源核查 / 最低补强 | 本轮实际修改 | 当前状态 |
| --- | --- | --- | --- | --- |
| [R-Q / Part] | [具体 concern，是否阻塞] | [原文、结果、作者确认或缺记录] | [新稿位置与改动] | [待核实/已改待复评/独立确认解决/部分/待证据] |

- **按影响排序。** 优先处理核心归因、公平比较、数据解释、关键设置和没有直接回答的问题；同时保留已有效的回答，避免反复重写引入矛盾。
- **批评不一定成立。** 能从原文反证时，回复中给出准确位置并改善可见性；必要时修正自身理解。不能要求下一轮 reviewer 接受主 agent 的内部结论。
- **写入候选稿。** 每项处理必须落到真实文本或明确的待证据项；“计划优化”“再解释清楚”不算完成。修改后检查同一 reviewer 各 Q、各 part 及不同 reviewer 共享事实是否一致。
- **措辞不能补证据。** reviewer 要求受控对照时，先找已有对照和实际配置；缺少必要事实则核实或诚实保留。作者确认写明其来源，不改称运行审计；未做实验不改写为已完成。

| 不满意的类型 | 可执行的强化方式 | 复评要检查什么 |
| --- | --- | --- |
| 没有直接回答 / 证据埋在后文 | 首句回答，把已有最强对照前置，补精确表格或段落指针 | 是否无需猜测就能找到回答和证据 |
| 核心方法与完整系统混淆 | 分开报告核心策略、辅助模块和系统终点，补已确认控制条件 | 归因是否仍依赖同时变化的监督或计算 |
| 数值、分母或设置不清 | 回到原计数和实际记录，说明样本、条件比例及配置范围 | 是否只澄清了局部结果却推广到全部实验 |
| 新颖性或相关工作解释不足 | 核对原文，比较目标、机制和已验证差异，承认未做的直接比较 | 是否把公式差异当成实证优越性 |
| 主张大于证据 | 给出有依据的较窄结论和具体修文落点，保留反例与代价 | 收窄后是否仍有足够证据支撑有价值的贡献 |
| 决定性证据确实缺失 | 在已授权范围内补证；否则标记缺口与影响 | 是否仍用承诺或小样本观察冒充解决 |

## 修改后进入下一轮

1. **记录实质变化。** 写明旧问题、本轮改动、新依据和仍缺什么；证据重新组织、补足遗漏回答或去除错误归因都可构成实质改进，前提是确实针对问题。纯换同义词或重复请求涨分不能支撑重评。
2. **先自查再冻结。** 核对数值、引用、匿名、字数/字符限制和跨块一致性；把本轮实际会提交的文本冻结。修改工作副本不能覆盖旧快照。
3. **全新独立复评。** 新 agent 读取原论文、原 review 与新回复，自行判断是否满意；不给上一轮 verdict 或作者变更辩护。旧 verdict 与修改表仅由主 agent 用来比较问题解决情况。
4. **不满意就继续修。** 新判定仍指出可修复问题时，回到核查与修改，而不是只向用户报一个低分。对新出现的问题核实其重要性；合理批评进入台账，不成立的批评用证据回应，不因 agent 不满意就扩大研究范围。
5. **已正面也看剩余问题。** 即使给出正面评分，影响正确性、关键披露或提交完整性的残留问题仍应处理；可选扩展与已明确披露的局限不自动变成必须完成的新任务。
6. **跟踪回退。** 分数下降或原 concern 再次出现时，检查是否新稿删掉了关键证据、限定或跨块上下文；保留不利判定。确需恢复旧段落时保留有用的新证据，形成新版本后再评。
7. **区分局部与全体。** 局部修改可先评受影响 reviewer；共享事实变化还需检查所有相关回复。最终声称整组通过时，须覆盖同一冻结版本中各 reviewer 的实际文本，不能拼接不同版本的最高分。

多轮优化可能表现为：首轮发现核心归因不清 → 将已有受控结果前置并区分系统结果 → 次轮仍指出控制条件未知 → 从真实记录或作者处核实后准确补写 → 新轮独立判断。关键进展来自每轮可定位的实质改动；没有新依据时，不把相同文本反复送评。

## 停止与最终交付

- **达到约定。** 主要 concern 得到独立确认，残余限制已准确披露，满足用户事先约定的验收口径且必要检查完成，即可结束；不自加“所有人必须满分”的目标。
- **仍有可做的改进。** 在授权与资源范围内继续核查、改稿和复评，不能把第一轮未通过当作任务完成。
- **证据已到边界。** 反复指向同一决定性缺口且没有可行的新事实或授权实验，交付未达状态、已做改进、缺口与下一步；不无限改写、不换评分标准，也不挑最高分隐藏其他轮。
- **资源已到边界。** 达到约定时间、轮次或预算时，报告最近一轮与当前候选稿状态；未复评的新稿单独标记，不能沿用旧分数。
- **最终文本再验。** 翻译、压缩、分块或实质修改后，新 agent 要读实际最终稿及全部 parts。评审后再修改须重评或明确“该修改尚未独立复评”；模拟通过不能等同真实审稿人改票。
- **完整归档。** 保留各轮输入清单/哈希、agent 初始化与实际暴露、完整 verdict、修改台账、技术失败和最终版本映射。报告哪些问题已解决、哪些只部分回应、哪些仍需证据，以及论文修改是承诺还是已经落实；准备好文件不代表已发布回复或上传论文。
