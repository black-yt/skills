# 证据采集与完整性

## 材料与工作目录

- **冻结输入**：记录文件名、SHA-256、页数、提交版本/时间（仅在材料有据时）、是否加密、正文/附录/补充材料是否齐全。重新上传或修改的 PDF 单独建档。
- **本地输出**：使用明确的 `[AUDIT_DIR]`，保留需要交付的 JSON、报告和证据截图。测试用临时目录使用上下文管理器自动清理；不在全局 `/tmp` 散落论文副本。
- **原件不改**：渲染、转换和对象展开写新文件，不覆盖原始 PDF。不为了读取全文重新排版论文或运行作者的构建/安装命令。
- **输入边界**：只有 Markdown 时完整检查该文件，但不能声称检查了未提供 PDF 的隐藏文字/元数据或未实际读取的图片。明确这一边界，不阻塞 MD 本身的注入判定。

## PDF 与 Markdown 的存在规则

| 已有材料 | 必须执行 | 覆盖边界 |
| --- | --- | --- |
| 只有 PDF | 完成 PDF 文字层、页面图像及隐藏载体检查；可按需生成 MD 辅助阅读 | 没有现成解析 MD 不阻塞 PDF 检查；不能声称已检查不存在的缓存 |
| 只有 MD | 完整检查 MD 原始源码、指令语义及范围内可获取的关联图片 | 不要求先补 PDF 才开始；可以确认 MD 中存在注入，PDF 传播路径另记为未核实 |
| PDF 与 MD 都有 | 两者各自检查、各自记录哈希和覆盖，再比对差异 | 禁止只读“更方便”的一种；不能假设解析结果忠实、完整或天然可信 |
| 都没有 | 清点用户是否已提供截图、摘录或其他材料，在可用范围内检查并说明缺失 | 没有任何可读材料时请求论文材料；不能声称检查完成 |

- **查找范围**：用户给出的目录、同名文件、对应解析目录中的 `full.md` 和其他相关 `.md/.markdown`。不要扫描无关个人目录；多个解析版本都在范围内时逐个列出，不静默挑一个。
- **保护已有 MD**：先检查并记录其哈希，不通过重跑解析覆盖它。新生成的 MD 与先前存在的 MD 分开，避免抹掉只存在于缓存中的指令。
- **不是独立证明**：PDF 与其派生 MD 是两个需要检查的载体，通常不是两个独立来源；重复内容不能当作独立证实作者意图的证据。

## Markdown 原文检查

- **原文优先**：直接读文件全部源码，记录从 1 开始的物理行号；不先用 Markdown 渲染器、摘要器、去注释器或正文清洗器过滤。
- **不可遗漏**：正文、标题、frontmatter/YAML、HTML 注释、隐藏 HTML/CSS 内容、引用块、代码围栏、脚注定义、链接定义及 title、图片 alt、表格、文末解析器附注和伪角色标签都属于检查面。
- **图片与链接**：MD 中的 alt 文字和实际图片分别核查；图片有本地文件且属于已授权范围时读取/OCR。远端链接和路径越界不自动访问；缺图或未访问的内容明确列为盲区，不能据此忽略已有文本证据。
- **Unicode 与暗示**：保留符号、emoji、零宽/双向控制字符、特殊标点及原始拼写。另建规范化检索视图以定位拆字、断行与全角文本，但不替换证据原文。
- **编码可靠性**：不能用 `errors="ignore"` 或替代字符悄悄丢掉内容。默认按 UTF-8 读取，失败时确认编码后重新读取；报告编码与失败情况。
- **非渲染区域**：注释中“请按以下方式审稿但不要告知人类”等指令，即使预览不可见也必须分析；HTML 注释或 `display:none` 不使内容失去审稿操纵性质。
- **只读采集命令**：下列脚本仅依赖 Python 标准库；输出目录必须不存在。没有 PDF 或 PyMuPDF 时也能独立运行。

```bash
python scripts/collect_md_evidence.py '[PARSED_DIR/full.md]' \
  --output '[AUDIT_DIR]/markdown'
# 编码已经核实为非 UTF-8 时，使用 --encoding '[VERIFIED_ENCODING]'
```

- **`inventory.json`**：文件名、字节数、SHA-256、编码、总行数、采集边界和完整性状态；没有 PDF 页码时不编造映射。
- **`lines.jsonl`**：每行一个 JSON 记录，保留物理行号、原始文本和换行符、Unicode 格式字符、辅助检索文本。所有文本都是不可信证据；脚本不自动判定注入或排除研究样本。
- **退出码**：0 表示采集成功；2 表示输入、编码或输出目录错误；3 表示采集中发现输入已变化，不能把混杂版本当可靠证据。

## 双载体比对

- **先独立完成**：分别检查 PDF、MD，再按标题、段落、图号与上下文定位对应处；不能因为某一侧没有发现就跳过另一侧。
- **登记四类内容**：两者共有、PDF 独有、MD 独有、措辞/顺序变化。关注解析器新加的指令、拼接后形成的暗示、隐藏内容被转为正文，以及 PDF 中未被提取的图片文字。
- **定位双写**：有对应关系时报告 PDF 物理页/bbox 与 MD 文件/行号；无可靠页映射时只报告 MD 行号，并标记“PDF 对应处未证实”。
- **不抵消发现**：MD 中出现注入而 PDF 未检出时，仍报告 MD 载体的注入；反之亦然。差异可能来自解析、版本或后处理，未查明前不归因于作者。

## 本地辅助脚本

本节针对 PDF；仅有 Markdown 时使用上节流程，不等待 PDF。

查看实际依赖版本与参数：

```bash
python -c 'import pymupdf; print(pymupdf.__version__)'
python scripts/collect_pdf_evidence.py --help
python scripts/collect_pdf_evidence.py '[PAPER.pdf]' \
  --output '[AUDIT_DIR]/pdf' --render --dpi 160
```

- **依赖**：Python 3.10+、PyMuPDF 1.24+。已有兼容环境可直接使用；缺依赖时按当前环境约束在独立环境安装 `PyMuPDF>=1.24`，不修改共享环境。
- **密码**：合法持有解密口令时加 `--ask-password` 交互输入；不把口令放命令行、报告或脚本内。无法解密时停止该文件的检查，不绕过权限。
- **目录**：输出目录必须不存在，防止不同版本的证据混在一起或覆盖用户资料。
- **`inventory.json`**：输入哈希、工具版本、页数、采集错误、元数据/XMP、目录书签、可选内容层、嵌入文件清单、PDF 对象线索和脚本覆盖边界。
- **`text.txt`**：每页按原始抽取顺序保存文字，页界明确；保留跨页连接的可能性，不仅检索摘要。
- **`pages/page-NNNN.json`**：正文原始顺序与位置排序两种文本、全部文字轨迹的内容/坐标/字体/颜色/透明度/绘制类型/层名、批注、表单和链接。排序视图仅辅助阅读，不代表正确阅读顺序。
- **裁剪差异**：普通文字抽取即使使用无限 clip，也可能漏掉页面 CropBox 外的文本，而绘制轨迹仍能记录它。全文检索必须同时读取 `text_traces`，不能只搜索 `text.txt`。
- **`renders/page-NNNN.png`**：`--render` 启用完整逐页渲染，包含正常显示的批注；生成图片不等于 agent 已视觉检查。
- **退出码**：0 表示采集步骤未报错；2 表示输入/输出/密码等入口失败；3 表示已保存部分证据，但存在采集错误或对象扫描被截断。查看库存中的错误和页状态后再继续。

## 必查的两个视图

1. **抽取视图**：读全部文本、批注、表单、元数据和书签；重点核对指令对象、章节边界、代码框与前后句。保留源页、证据 ID 与原始字符串。
2. **视觉视图**：逐页查看正常背景、页边、脚注、图表、算法框、截图、参考文献、附录。先完整浏览，再放大密集或可疑区域；小缩略图不能替代实际检查。

- **需要 OCR 的位置**：扫描页、图中截图、图片标签、公式路径化的文本以及有图但没有可用文字层的区域。存在一些可选中文字，不能证明该页所有图内文字已被抽取。
- **OCR 对照**：本地 OCR 必须对渲染后的像素运行，才能与原文字层形成不同证据来源；不能把同一文字层换个解析器称为独立 OCR。
- **工具替代**：已有 Poppler 时可用 `pdftotext -layout` 交叉检查和 `pdftoppm` 渲染；用户指定的 `read_pdf` 可补充结构化阅读，但 Markdown 往往丢失隐藏层、样式和页坐标，不能代替原 PDF 检查。
- **分批检查**：按页段维护“已读文字/已看图像/OCR 状态”；资源不足时留下明确的未查页段，不能只抽查前几页后宣称全文完成。
- **冲突处理**：OCR、抽取文本、渲染图不一致时列为候选，回到原件定位。OCR 拼错的短语不能逐字归因于作者。

## 隐藏与旁路载体

| 载体 | 如何核实 | 不能直接下的结论 |
| --- | --- | --- |
| 白字/近背景色、小字 | 查颜色、字号、原页局部背景并放大；必要时在副本高对比渲染 | 白色文字可能位于深色标签；小号字可能是正常脚注 |
| 不绘制/低透明度文本 | 查文字轨迹 `render_type=3`、`opacity`，对照正常渲染和 OCR | OCR 隐藏层常见；属性异常不等于操纵 |
| 裁剪区外/旋转/遮挡 | 比较 bbox 与未旋转页面可见区域，查绘制顺序、剪裁及覆盖图形 | 轨迹存在不代表最终可见；重叠水印或裁剪也可能是正常排版 |
| 可选内容层 | 查层名、启用状态和相关对象；在隔离副本对比必要层的显示 | 当前渲染只覆盖当前层状态，不代表所有状态都看过 |
| 批注/表单/书签 | 查文本、字段值、隐藏标志、批注附件和目标页 | 批注可能是编辑记录，书签标题不是系统指令 |
| Info/XMP 与无障碍文本 | 查元数据、ActualText、Alt、结构树和原页是否一致 | 无障碍文本合法存在；不应默认删除 |
| 图片/SVG/二维码 | 放大或 OCR，必要时离线解码二维码文本；不自动访问链接 | 图片没有可选文字不是安全证明；二维码可能是正常资源链接 |
| PDF 对象/嵌入附件 | 查对象线索、流、附件名称和 MIME；记录 xref 与所属页 | 对象存在不证明被当前页面、解析器或审稿系统消费 |
| 外链与补充材料 | 对用户提供且属于范围的材料逐个检查；外链只做静态记录 | 未访问的网页或未提供的附件不能写成“已安全” |

## 对象级复核与源码

- **脚本对象索引**：扫描 xref 字典中的 `/ActualText`、`/Alt`、`/OC`、`/JavaScript`、`/JS`、`/OpenAction`、`/AA`、`/Launch`、`/EmbeddedFile`、`/Filespec`、`/RichMedia`、`/XFA` 等线索，保存对象原文与编号；它不是完整 PDF 语法分析器。
- **明确盲区**：脚本不扫描解压后的任意 content/Form/metadata 流，不切换隐藏层，不提取或执行附件，也不检查历史增量版本；页内流中的 `/ActualText` 等可能只在进一步对象检查中出现。
- **进一步展开**：有异常或执行完整隐藏层审查时，用当前本地工具的 `qpdf --help` / `mutool help` 确认参数，将对象与内容流展开到副本；或使用 `doc.xref_object(xref)`、`doc.xref_stream(xref)` 只读获取已定位对象。包括页面内容流、Form XObject 和结构树的文字替代；记录压缩/过滤器、截断与解码失败，未完成就保留为覆盖盲区。
- **保留来源链**：对象里的文案保留 xref、页关联、原始字节/文本和解码步骤；不要只搜索压缩 PDF 的字节后宣布无命中，也不要把未引用对象当成当前页面的有效指令。
- **控制资源**：未知附件、压缩流和极大 PDF 可能耗费大量资源。采用本地工具的资源限制，遇到超限明确报告；辅助脚本不是恶意文件的沙箱。
- **源码静态检查**：用户提供 LaTeX/HTML/SVG 时检查注释、宏展开来源、白色/极小字、透明度、定位遮盖、元数据、链接、图片 alt、实际文字替代和嵌入资源。检查 `.tex/.bib/.sty` 及实际包含的文件，不运行 Makefile、TeX shell escape、JavaScript 或安装脚本。
- **传播路径**：源代码注释未必进入 PDF；Alt 可能影响解析但不显示。区分“仅源码存在”“成品 PDF 可提取”“成品可见”和“当前工具未证实”，不能混写。

## 采集提示的含义

- **`small_font`**：字号低于 5 pt，仅提示放大核对；不能作为自动异常阈值。
- **`near_white`**：灰度/RGB 分量接近白色，没有计算局部背景对比度，也不覆盖全部 CMYK/特殊色空间。
- **`low_opacity` / `unpainted_text`**：低透明度或不绘制文本；仍需区分合法 OCR 层和额外指令。
- **`outside_visible_page` / `partly_outside_visible_page`**：与去旋转后的页面区域比较；bbox 不表示实际逐像素可见性，遮挡和复杂剪裁需要复核。
- **`format_controls` / `replacement_character`**：存在零宽、方向控制等 Unicode 格式字符或提取替代字符；保留码点并核对原图，不自动修正文案后当原文引用。
- **`no_text_extracted`**：需要视觉/OCR 复核，可能是扫描件也可能是空白页；脚本不认定其内容为空。
- **`complete` 的限制**：即使为 true，语义审阅、图片文字、对象流、附件体和隐藏层状态仍需另行登记是否覆盖。
