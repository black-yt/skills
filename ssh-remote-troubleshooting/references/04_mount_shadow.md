# 被挂载遮住的文件与共享盘模型

## 为什么同一路径会占两块盘

- 在共享存储挂载之前写入某目录，数据可能落在系统盘上；后续挂载只遮住它们，不会释放底层磁盘空间。
- 正常访问 `[SHARED_MODEL_DIR]` 可能是 `virtiofs`、NFS 或其他共享文件系统；被遮住的同名目录却仍属于系统盘的 xfs/ext4。
- 文件系统类型只是线索，必须比较挂载目标、设备号与根目录设备号。共享路径和底层路径不是同一批 inode。
- **不能直接删除正常共享路径来释放底层系统盘空间**，也不能卸载正在使用的共享盘来调查。

## 独立只读视图

下面命令需要实际的 mount namespace 权限；权限不足时停止这条检查，不在主命名空间卸载共享盘。先将占位路径替换为真实路径在 `/` 下的相对部分。

```bash
sudo unshare -m --propagation private bash <<'SH'
set -eu
view=$(mktemp -d /tmp/root-storage-view.XXXXXX)
cleanup() {
    if mountpoint -q "$view"; then
        umount "$view" || return
    fi
    rmdir "$view"
}
trap cleanup EXIT
mount --bind / "$view"
mount -o remount,bind,ro "$view"
relative='[MOUNT_PARENT]/[ACCOUNT]/models'
live="/$relative"
underlying="$view/$relative"
findmnt -T "$view" -o TARGET,FSTYPE,OPTIONS
findmnt -T "$live" -o TARGET,SOURCE,FSTYPE
stat -c '%d %n' / "$underlying" "$live"
du -sh "$underlying"
SH
```

- 使用普通 `--bind /`，不用递归 `--rbind`，否则子挂载也被带入，无法看见遮蔽的底层内容。
- 只读 remount 与清理发生在私有命名空间；确认输出中的视图包含 `ro`。
- 上例不删除任何模型。路径不存在、设备不符或挂载检查失败时停止，不把空结果解释成可安全删除。
- 私有命名空间隔离挂载操作，**不隔离文件数据修改**；通过视图删除文件仍会真实修改系统盘，因此调查阶段必须只读。

## 比较、迁移与释放空间

1. **列清范围**：列出底层目录、共享盘目标、普通文件、空目录、链接和特殊文件；目录名不同也可能是同一个模型，不能仅凭名字判断。
2. **逐文件校验**：在只读视图存活期间执行 `python3 [SKILL_DIR]/scripts/compare_trees.py '[UNDERLYING_MODEL]' '[SHARED_MODEL]'`。脚本逐文件读取全部内容并比较 SHA-256，大小相同不足以判定一致。
3. **不一致则迁移**：共享盘缺少的文件先复制到明确的新目标，保留原件和现有共享文件；同名不同内容不覆盖。先检查目标空间，完成复制后再对最终目标完整校验。
4. **验证使用者**：清理源文件前检查 `/proc` 中的 fd、cwd、exe 和 maps，以设备号与 inode 识别旧文件引用，不能只按路径字符串搜索。扫描被拒绝时不能声称已证明无人使用。
5. **再次检查**：对照校验时的源/目标设备、inode、大小、mtime/ctime 和目录清单，确认没有变化；有变化则重新核验。校验和一致不意味着未来绝不会改变。
6. **精确清理**：仅在任务已授权、共享目标完整且源无占用时，使用新的私有可写 bind 视图处理已核实的源目录。校验设备号仍等于系统根设备号，目标目录没有符号链接或子挂载。不得对正常共享路径运行递归删除。
7. **验收**：检查系统盘可用空间、共享文件清单与元数据、原有任务和对话状态；关闭视图并移除本次临时挂载点。

本 skill 不附自动删除模型脚本。链接、分片缺失、文件正在变化、共享盘未挂载或源仍在使用时保留源；不要以“目录叫 cache”为删除依据。

## 防止挂载缺失时再次写入系统盘

- 首选在模型下载/训练入口检查 `findmnt -T '[MODEL_DIR]'` 的目标、预期设备和文件系统；不符合预期就失败退出。`mountpoint` 仅检查精确挂载点，模型子目录通常不是挂载点。
- 只有当底层 `models` 已清空、用户希望阻止 fallback 写入、文件系统和权限支持时，才考虑给**底层空目录**设置 `chattr +i`。
- 在私有可写 bind 视图中先比较设备号并确认目录为空，再设置属性；不要对正常共享路径设置 immutable。普通 `chmod` 不能可靠阻止 root 写入。
- 用唯一临时文件名在底层视图实测创建失败，并确认共享盘仍挂载、原文件未变。禁止通过真的卸载生产共享盘测试。
- immutable 只保护当前文件系统上的该目录，不是自动挂载方案；重建机器或更换底层文件系统后需要重新核查。挂载失效时应明确报错并恢复挂载。
- 取消保护也必须从私有底层视图执行：确认设备号等于 `/` 后 `chattr -i '[UNDERLYING_EMPTY_MODELS]'`，随后卸载视图。记录保护位置、验证结果和取消方式，避免后续维护者误以为共享盘坏了。
