# 从科学内容到原生 draw.io

## 已融合的方法

参考 [codex-paper-figure-skill](https://github.com/pengqianhan/codex-paper-figure-skill)，对照其 `version: 0.0.1`、[commit `5538ad98a8724ecb4ed70102514cd9e51c00c0ee`](https://github.com/pengqianhan/codex-paper-figure-skill/tree/5538ad98a8724ecb4ed70102514cd9e51c00c0ee) 的工作流。本 skill 使用了以下做法，并配有自己的可运行代码：

- **先确定科学关系**：先列实体、标签、输入输出、独立分支和反馈关系，再做布局；每条边可追溯到论文或用户描述。
- **视觉参照后重建**：原图或生成草案用于构图参照，最终创建原生 `.drawio` 单元。
- **编辑优先**：文字、形状、箭头、图标与分组可以分别操作；图片不承担整张图的文字和科学关系。
- **连接线通道**：先安排主要流向与反馈线的通道，端点靠近逻辑相关边，避免穿过文字、节点和无关模块。
- **图标可追溯**：实际下载后核对作者、许可和署名；许可不明确的素材不进入案例。
- **实际渲染验收**：检查 XML 结构后，在 draw.io 中加载、导出并查看。交付主文件和可重现代码，同时说明未解决的差异。

本实现重新编写 XML 生成器、图元、案例、图标转换和导出器，没有复制参考仓库的图案或示例输出。两者都把 `.drawio` 作为主交付格式。

## 画图前的简报

先在任务工作目录保存一份简短 brief；不要把整篇论文当成图内文案。

```text
科学信息：这张图只说明哪一个机制、比较或流程？
来源：论文版本/页码/图号，或用户提供的方法描述。
画布：宽高比例、最终放置尺寸、单栏/双栏。
实体：id / 名称 / 数据、模型、状态、指标或容器 / 所属区域。
标签：必须逐字保留的术语、变量、单位、panel 字母。
关系：source_id -> target_id / 输入、输出、反馈、训练、检索等含义 / 来源。
分区：阅读顺序、昼夜/训练推理/实验组别、共同视觉编码。
图标：概念、来源页、作者、许可、实际文件与转换方式。
验收：必须出现的分支、冻结状态、回流、图例、数值与交付格式。
```

- **不确定关系**：标明缺口，回查正文或向用户问科学问题；不要为填满版面补一条箭头。
- **标签长度**：模块用短术语，长解释放图注。完整图题和摘要仅在用户需要或源图本来包含时绘制。
- **原图重绘**：按背景分区、容器、图标、连线、文字五类拆开测量；以几个共同锚点对齐，先纠正大的位置和尺寸。
- **文字转图**：可以用图像生成探索布局；图像里的文字不视作准确标签，最终重新写入 `mxCell.value`。

## 重建顺序

1. 创建 `mxfile → diagram → mxGraphModel → root`，保留结构 cell `0` 和 layer `1`。
2. 放区域背景和主模块，用一致的颜色、线宽、字号和对齐方式编码同类对象。
3. 先画主要关系，再安排反馈与支路。流程连接线使用 `source`/`target`，在需要时写明确锚点和 waypoint。
4. 添加可辨认的图标、重复 token、latent 块、曲线 marker 和必要的省略符；只分组实际需要一起移动的对象。
5. 添加真实文字。手绘扰动只用于形状，标题、正文与数学标签保持稳定基线。
6. 在 draw.io 中导出预览，按区域核对，再按最终版心尺寸复查。先修错误关系、遮挡和文字，再调微小线条。

## 交付核对

- **科学关系**：沿 brief 的每条边在图上走一遍，检查端点、方向、独立分支和反馈；检查冻结状态与模型选择的含义。
- **视觉**：同级文字对齐，没有文字被箭头或前景遮住；同一类型图标风格一致，最终版心下标签可读。
- **编辑**：实际选择并编辑文字、移动模块或修改 stencil；主文件含原生单元，而非一张整图截图。
- **证据**：XML 验证、draw.io 导出和回读报告各自保存。程序检查不能判断每条科学关系是否正确，需人工对照源文。
- **范围**：提供 `.drawio`、预览、必要的 PDF/SVG 与源代码；明确图面转录数据、图标署名和视觉差异。
