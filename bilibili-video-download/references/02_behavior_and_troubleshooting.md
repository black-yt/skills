# 工作原理与故障排查

## 实际执行链

`scripts/bilibili_download.py` 是完整实现，不依赖仓库外的辅助脚本：

1. 从 URL 或文本提取 `BV` 号，调用 `x/web-interface/view` 获取标题、UP 主、`aid`、`cid` 与分 P。
2. 调用 `x/web-interface/nav` 取得 WBI 所需的两个 key；游客的 `nav` 响应可能报告未登录，但仍提供 key。脚本用当前内置混排表、时间戳和 MD5 生成 `w_rid`。
3. 调用 `x/player/playurl?fnval=16` 请求 DASH。`accept_quality` 是理论可选列表，实际可下载画质以 `dash.video` 为准；未指定时取实际最高，指定后取不高于目标的最高可用画质，同档选择带宽最大的流。
4. MP4 模式分别下载视频/音频 `.m4s`，由 ffmpeg 复制封装为 MP4；没有独立音频流时仅重封装视频。`--mp3` 再从 MP4 转码，`--mp3-only` 优先利用同名本地 MP4，否则只下载音频流并转码。MP3 写入标题、UP 主和 BV 来源元数据。
5. 已存在且未传 `--force` 的成品默认跳过；ffmpeg 先写同目录临时文件，成功后才替换成品，失败时保留原文件。成功后清理本次 `.tmp_parts/` 片段。脚本不支持断点续传，失败的分 P 再运行时会重新下载其流。

## 参数与边界

| 选项 | 行为 |
| --- | --- |
| `--qn 80` / `--qn 1080P` | 指定目标画质；实际流不足时降档。`--list` 查看理论与实际可用档。 |
| `--interactive` | 先显示第一个目标分 P 的画质并等待输入；多 P 仍逐 P 取实际可用流。 |
| `--page N` / `--all` | 指定一个分 P 或全部分 P；默认只取第一个。 |
| `--mp3` / `--mp3-only` | 前者保留 MP4 与 MP3；后者只要求 MP3，不下载视频流，但可能从已有同名 MP4 转码。 |
| `--mp3-bitrate 0..9` / `320k` | VBR 质量或固定码率；其他格式直接报参数错误。转 MP3 是有损编码，不能改善源音频质量。 |
| `--cookie-file` | 从仓库外私有文件读取登录态；`--cookie` 仍可用，但明文命令行会暴露给 shell 历史/进程列表。 |
| `--ffmpeg` / `FFMPEG_BIN` | 指定 ffmpeg，优先级高于 PATH；合并 MP4 和导出 MP3 均需要它。 |
| `--force` | 覆盖同名成品；不要在未确认输出目录和原文件时使用。 |

## 按首个错误排查

- **无法解析 BV 号**：只接受普通投稿的 `BV` 号或包含它的链接；`ep/ss` 番剧、AV 号、互动视频和列表页不在范围内。分享文本须包含完整 BV 号。
- **`view`/`nav`/`playurl` 失败**：先确认 API 连通性、Cookie 有效性和视频是否仍可访问。`-400` 可由 WBI 签名或风控引起；短暂故障有限重试，持续失败时检查接口变化，不改造绕权请求。游客 `nav` 的 `-101` 不必然使 WBI key 不可用。
- **仅有低画质或标注需登录**：核对 `--list` 的 `accept_quality` 与 `dash.video`、账号状态及对应权益；不要把理论档位当作实际流，也不要承诺登录后一定有 4K/8K。
- **CDN 403、超时或中途断流**：核对网络、Referer、视频可访问性及是否触发限流；稍后重试。未完成 `.m4s` 不是成品，脚本会在下次运行重新下载该流。
- **没有独立音频流**：`--mp3-only` 会明确报错；MP4 模式可生成无声视频。需要 MP3 时先核查视频本身是否有音频，不凭空生成空 MP3。
- **找不到 ffmpeg 或 `libmp3lame`**：按安装 reference 检查版本、可执行路径和编码器；缺 ffmpeg 会失败退出，不应报告为下载成功。
- **文件已有但内容不对**：脚本按标题命名，跨 BV 同名可能碰撞；为每个 BV 使用独立 `--dir`，检查 ffprobe。需要重下时确认目标后使用 `--force`。

本实现依赖当前 B站 Web 接口行为；接口字段、签名或风控变化时，先保留脱敏的状态码、响应字段与复现命令，再更新脚本并重新验证。不要记录 Cookie、签名密钥或完整含敏感参数的请求日志。
