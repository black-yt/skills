# 文件隔离、干净复原与产物导出

## 按要求选择文件边界

共享目录挂载本身是正常的部署与导出方式。要验证的是 **agent 能否改动用户要求保护的会话外文件**，不能仅凭“运行在容器里”或“设置了临时 HOME”作保证。

| 需求 | 可用方式 | 需要核对 |
| --- | --- | --- |
| 部署端读取共享软件和缓存 | 只读挂载，或准备阶段复制到会话 | 实际 mount 选项、文件所有者和 agent UID/ACL；不修改共享缓存 |
| agent 的写入只留在会话内 | 无项目挂载的独立执行容器，或另设已验证的文件系统访问边界 | 不把可写宿主目录、Docker socket、宿主 X11 socket 传入 agent |
| 通过共享目录输出产物 | 仅映射用户指定的输出位置，或由控制端导出 | 该输出目录是明确的持久写入例外；不能同时宣称所有写入都只留在容器 |
| 独立内核或完整 VM 快照 | 用户指定的 VM/KVM 平台 | 容器共享 worker 内核；本 skill 的干净重建不是 VM 内存快照 |

- **普通用户：** 安装阶段可用专用容器 root，随后以普通用户运行 GUI、agent 和控制服务。普通 UID 不能阻止写入允许该 UID 或所有人写入的共享目录，仍需核对权限和有效挂载。
- **部署权限：** 软件/venv 保持安装用户所有，让 agent 可读、可执行；HOME、XDG、文档和截图临时目录归会话用户。不要把整个项目改成 `777` 来解决启动失败。
- **两种部署：** 现有 `assets/runtime/submit_rjob.sh` 使用共享目录，方便准备缓存和回传证据。要求更严格的文件边界时，可改用 [04](04_rjob_and_acceptance.md#独立代码包模式) 的独立代码包；它是另一种模式，不应悄悄改变用户原有挂载。
- **有效配置：** 检查最终 pod spec 与容器内 mount 信息。提交命令没写 `--mount`，不代表平台没有自动注入其他 volume；`host-network=false` 也不是文件权限设置。

## 验证会话外文件未受影响

1. **外部基线：** 在用户项目创建专用对照文件，记录其内容 SHA256、权限，以及选定代码/解释器的校验值。不要使用真实私密文档作为探针。
2. **边界探针：** 从 agent 所用 UID 检查对照文件是否可见、可读及相关目录是否可写；核对预期不可访问路径。只验证一个 `600` 文件读失败，不能证明其余共享目录都不可写。
3. **真实会话修改：** 让 agent 通过应用创建/保存测试文件；另在容器临时目录写一个唯一标记，用于后续区分容器重建与应用重启。
4. **外部回查：** 比较外部文件的校验值和权限，并确认容器路径没有意外映射到开发机。将结果与挂载/权限检查一起报告；几个文件没变化不等于任意恶意程序都无法逃逸。

不执行破坏性写入来证明隔离；需要写探针时，只使用本任务专用、可丢弃的位置。

## 从同一基线重建

**基线内容：** 记录镜像标识（有 digest 时优先用 digest）、应用版本、依赖锁定、代码包清单、初始文档与配置。软件包/wheel 可以缓存，但会话 HOME、XDG、显示和应用进程每次新建。重建时重新拉取滚动 main 或未固定依赖，会让“同一基线”失去含义。

| 阶段 | 动作与通过条件 |
| --- | --- |
| A 初始会话 | 保存初始文档 SHA256、是否存在测试产物、可选初始截图和代码包清单 |
| A 运行后 | 真实保存修改，确认 SHA256 已变，生成文件和容器临时标记确实存在 |
| A 删除前 | 完成日志/截图/视频导出并验证；无共享输出的容器删除后无法再取回未导出文件 |
| B 新会话 | 删除 A job，用同一基线创建新的容器；仅重开应用或重新连接 HTTP 不算重建 |
| B 验收 | 初始文档 SHA256 恢复，A 生成的文件与临时标记消失，依赖/代码包清单一致；外部对照文件不变 |

- **截图判据：** 核对应用和初始内容。时钟、鼠标、插入光标闪烁等会造成像素差异；逐字节相同是额外证据，不是所有桌面必须满足的条件。
- **复原范围：** 这是丢弃会话修改、重建干净环境；不保留任意时点的内存、进程、网络连接或 GUI 快照。用户要求恢复到中途状态时，需另选支持该能力的平台。
- **失败处理：** B 仍有旧文件时，先查共享卷、持久 HOME/XDG、复用的软件可写目录和旧 run ID。导出未完成或校验失败时，先保留 A，处理失败后再清理。

## 只导出明确的产物

**传输方式：** 可使用用户指定的共享输出目录、受认证的下载服务或 SSH/SCP。控制端主动下载，使 agent 不需要写宿主目录；公开接口需要合适的 TLS/隧道和认证，不能直接开放任意文件浏览。

| 内容 | 建议处理 |
| --- | --- |
| 应用结果、任务日志、验证 JSON、PNG、MP4 | 显式加入允许导出的目录/文件类型；同时限定解析后的文件路径，不只看后缀 |
| `.env`、模型 key、控制 token、代理脚本、cookie、shell profile | 排除；不要把整个 HOME、源码或配置目录递归当成产物 |
| 上游 agent debug 目录 | 检查实际日志结构与内容，再按需导出；截图和完整模型响应可能带来隐私与容量开销 |
| 文件清单 | 保存相对路径、字节数和 SHA256；客户端逐项回算校验，归档与清单一起保留 |

- **先稳定产物：** 等待模型任务完成及日志落盘；向 FFmpeg 发送 SIGINT 完成封装后，再用 ffprobe 检查 codec、尺寸和时长。不能在视频仍写入时宣称归档完整。
- **容量：** 设置会话时长、步数、录屏和导出总量限制，统计实际字节数，不只依赖响应的 Content-Length。已测示例采用 32 MiB 视频与 64 MiB 原始导出总量上限，它们是样例参数。
- **服务端：** 使用允许列表、限制成员数量/总量，拒绝符号链接与目录逃逸；不用来自请求的任意文件路径。控制请求和鉴权头不写入日志。
- **接收端：** 下载到新的专用目录，检查归档成员；拒绝绝对路径、`..`、软/硬链接、重复或越界目标，限制解包总量。不盲目 `extractall`，也不沿已有目录中的符号链接写入。
- **凭据检查：** 导出前检查日志、打包排除项和实际成员；必要时用已知密钥做匹配检查，仅输出是否泄漏，不回显匹配值。发现泄漏先修正输出与归档，再交付。
- **完成条件：** 本地文件可读取、清单校验通过、PNG 实际打开、MP4 有效、应用结果符合任务；HTTP 200 或“归档存在”不足以判定通过。

## 已测实例的解释

2026-11-05，IrisGUI + Mousepad 的两个全新 CPU rjob 完成 A/B 验收：A 通过模型保存中英文原文件及另存文件，B 恢复初始文档、移除产物与临时标记，代码包清单一致；两次初始 PNG 也逐字节一致。外部选定文件的 SHA256/权限不变。

A 经认证下载 41 个文件，归档 712,450 字节；B 下载 8 个文件，归档 19,651 字节。A 文件清单校验通过，扫描未发现真实模型 key 或 `.env`。这证明当时配置下的目标任务和导出/重建链路，不作为任意应用、恶意代码或其他挂载配置的隔离保证。模型与安装细节见 [06](06_existing_agent_integration.md)。
